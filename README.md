# KolektaPH

Real-time garbage truck tracking, barangay SMS alerts and the "Ask Kolek" assistant for the 14 barangays of the City of Carmona, Cavite.

> _Alam mo kung kailan. Alam mo kung saan._

One Expo (React Native) codebase, three apps:

| App                 | Runs on                                                  | Who                     |
| ------------------- | -------------------------------------------------------- | ----------------------- |
| Resident            | Web (installable PWA), Android                           | Residents of Carmona    |
| Driver              | Android development build (background GPS during shifts) | Garbage truck drivers   |
| City ENRO dashboard | Web, desktop-first                                       | City environment office |

**Current phase:** UI/UX and core functionality on mock data and a deterministic truck simulator. There is **no database or backend yet**. Screens talk only to the service interfaces in `src/services/`, so a real backend can replace the mocks later.

## Requirements

- Node LTS (v24, through fnm), Watchman
- JDK 17 (Zulu) and the Android SDK (Android Studio), for Android builds

## Run

```bash
npm install
npm run web          # resident / ENRO web app at http://localhost:8081
npm run android      # build and install the Android development build (first build is slow)
npm start            # dev server only (the installed dev build connects to it)
```

## Quality checks

```bash
npm run check        # typecheck + lint + tests
npm run doctor       # expo-doctor dependency/config checks
npm run format       # prettier
```

## Project layout

```
src/app/          routes only (expo-router): /demo, /resident, /driver, /enro
src/components/   UI kit and the platform-split map (KMap.tsx native / KMap.web.tsx)
src/features/     pure TypeScript domain logic (ETA, alerts, coverage, reports, Kolek)
src/services/     service interfaces + mock implementations
src/simulator/    deterministic truck simulator and demo clock
src/data/carmona/ sample barangays, routes, trucks and schedules (sample data)
src/i18n/         Filipino (default) and English strings
__tests__/        Jest tests
```

`android/` and `ios/` are generated by `expo prebuild` (Continuous Native Generation) and are not committed. Configure native behaviour in `app.json`.

## Demo: driver ↔ City ENRO

On the web, open `/driver` and `/enro` in two tabs of the same browser. They share the mock
server (localStorage), so a driver's tap (e.g. **PUNO**) shows up on Live Operations within a
couple of seconds. The demo PIN for every truck is `1234`. "Demo: gayahin ang walang signal" on
the driver's GPS page shows the offline queue at work.

## Demo: reports and "Hindi nadaanan"

- **Resident → ENRO → driver:** send a report from **Report** in `/resident` (4 steps: what, photo, where, send). It appears in `/enro/reports` sorted by priority, with a suggested handling. Dispatch it to a truck on route and it shows up as "Espesyal na koleksyon" in that truck's `/driver/shift`. The crew's before and after photos close the loop, and the resident's "Aking mga report" shows the timeline and can reopen within 48 hours or rate.
- **Missed-street claims:** on a collection day, "Hindi nadaanan ang kalye namin" on the resident Home checks the street against the truck's GPS trace. Use the demo clock to reach each outcome: route not finished (ETA), not segregated, crew not at fault (truck full or road blocked), verified miss (ticket), or "please send a photo". `/enro/missed` lists missed streets per day with "Iskedyul ang muling pagkolekta".

The 12 sample tickets (KPH-…-000101 to 000112) and their pictures are sample data. Resetting from `/demo` restores them.

## Driver app on a phone (Android)

Real GPS recording needs the Android build: location is recorded by a foreground service only
while a shift is running ("naka-shift" notification), with the "while using the app"
permission. The driver's "GPS at pagpapadala" page shows points, uploads and any gaps, which is
what a field test checks. To share an installable APK with crews (needs an Expo account):

```bash
npx eas-cli@latest login
npx eas-cli@latest build -p android --profile preview
```

## Map data

- Barangay boundaries and populations are real: OpenStreetMap, where the population tags match the PSA 2024 Census.
- Truck routes follow real Carmona streets but are **sample** routes.
- Both are generated once into static JSON (see `src/data/carmona/SOURCES.md`):

  ```bash
  node scripts/data/build-carmona-data.mjs
  ```

- On web, maplibre-gl loads its worker from `public/maplibre/`. `npm install` copies it there automatically (the `postinstall` script).

## Data notice

All numbers, schedules and routes in `src/data/` are **sample data** until they're validated with the City of Carmona ENRO. The app labels them as sample data in demo mode.
